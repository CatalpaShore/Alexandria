# 数据与媒体源迁移

[文档导航](README.md) · [备份的界面操作](USER_GUIDE.md#backup-migration) · [首次接入](GETTING_STARTED.md)

Alexandria 18+ 使用 React / Ant Design / GSAP 界面与 Node / SQLite 后端。迁移重点是保留媒体 ID、用户记录和独立附件；普通扫描只读使用源媒体。

## 操作顺序

1. 创建数据库与附件的完整备份。停止正在访问该数据库的服务，把数据目录复制到独立位置；不要直接使用唯一正式库试运行。
2. 使用 `DATA_DIR` 指定副本目录，或以 `AMW_DATABASE_PATH` 指向数据库副本。保留原媒体的分类、来源名称和相对目录组织。禁止多个服务实例同时访问同一 SQLite 文件。
3. 涉及数据库结构更新时，先以 `VACUUM INTO` 创建包含已提交 WAL 内容的一致性快照，位于数据库旁的 `upgrade-backups/`。无法识别的未来结构版本会被拒绝打开。
4. 首次扫描读取完整媒体文件计算 SHA-256，大库 / NAS 可能较慢；随后按大小与 mtime 缓存指纹。全新空库会先导入本地资料和字幕，让作品在指纹校验期间可浏览；有历史记录的影库仍先完成指纹匹配再导入。先完成扫描并保留数据库，再移动或重命名文件。
5. 从首页“接入媒体库”预览目标目录。保存前自动创建数据库快照；空目录需要明确勾选。配置改变索引来源，不复制或搬动媒体。

## 匹配和记录保护

相同分类、来源名称和相对路径保持媒体 ID，根目录变化不会重建用户记录。不同路径仅在完整指纹对应“一个失联条目 + 一个新条目”时合并；同一物理文件改变来源标签也可识别。重复副本、歧义指纹或指纹缺失时保留独立条目。

收藏通过路径别名衔接，播放记录更新路径，片单和精彩片段保留媒体 ID 引用；其他个人档案的快照也更新精确匹配的路径。扫描不删除失联馆藏，因此磁盘掉线、配置变化或空目录不会级联清空记录。离线条目仍可能计入统计，播放器会提示源不可读取。

本地 NFO / JSON 按字段导入，手动修改和 `metadata_overrides` 优先，已取得的外部资料不会被旁车文件批量覆盖。读取有大小限制，并拒绝外部 XML 实体声明；不会跟随元数据里的远程 URL 下载内容。

## 自有资料与恢复

人物别名 JSON 可放入数据目录的 `actor-aliases.json`，或通过 `AMW_ACTOR_ALIASES_PATH` 指定。自有资料定义可使用 `official-topic-sources.json` / `official-actor-sources.json`。公开仓库不附带个人资料表，修改后重启生效。

恢复前先停止服务并备份当前数据，再把完整备份恢复到独立目录。数据库快照不包含封面、字幕缓存、精彩片段和收藏文本，这些附件需要单独或随数据目录备份。

迁移机制使用独立中性测试夹具验证；真实完整库迁移与大规模 NAS 负载仍需在实际部署中验收。首次资源接入见[上手指南](GETTING_STARTED.md)。
